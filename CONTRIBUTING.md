## Development Environment

We use **renv** to guarantee a reproducible development environment.

### First time (cloning the repository)

``` r

# 1. Clone the repository
# git clone https://github.com/worldjusticeproject/WJPr.git

# 2. Open the project in RStudio or R

# 3. renv activates automatically. Install the dependencies:
renv::restore()

# 4. Check that everything is installed:
devtools::load_all()
wjp_check_deps()
```

### Adding new dependencies

``` r

# 1. Install the package
renv::install("new_package")

# 2. Declare it in DESCRIPTION (Imports or Suggests)

# 3. Update the lockfile
renv::snapshot()

# 4. Commit renv.lock
```

### Updating existing dependencies

``` r

# Update all packages
renv::update()

# Save the changes
renv::snapshot()
```

## Naming Conventions

### Files

| Type           | Convention               | Example                       |
|----------------|--------------------------|-------------------------------|
| Chart function | `{type}Chart.R`          | `barsChart.R`, `radarChart.R` |
| Utilities      | `{name}.R`               | `utils.R`, `check_data.R`     |
| Data           | `data.R` (documentation) | \-                            |

### Functions

| Type | Prefix | Example |
|----|----|----|
| Charts | `wjp_` | [`wjp_bars()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_bars.md), [`wjp_radar()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_radar.md) |
| Utilities | `wjp_` | [`wjp_fonts()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_fonts.md), [`wjp_check_data()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_check_data.md) |
| Theme | `WJP_` | [`WJP_theme()`](https://worldjusticeproject.github.io/WJPr/reference/WJP_theme.md) |

### Standard Parameters

All chart functions MUST use these parameter names when applicable:

| Parameter     | Description                            | Type         |
|---------------|----------------------------------------|--------------|
| `data`        | Data frame with the data               | data.frame   |
| `target`      | Column with the numeric values to plot | string       |
| `grouping`    | Grouping column (X or Y axis)          | string       |
| `colors`      | Column used for colors                 | string       |
| `cvec`        | Named vector of hex colors             | named vector |
| `labels`      | Column with labels                     | string       |
| `order`       | Column with the display order          | string       |
| `ptheme`      | ggplot2 theme                          | ggplot theme |
| `show_legend` | Show the shared top legend             | logical      |

## Anatomy of a Chart Function

Every chart function should follow this structure:

``` r

#' Short descriptive title
#'
#' @description
#' `r lifecycle::badge("experimental")`
#'
#' Detailed description of what the function does.
#'
#' @param data Data frame containing the data to plot.
#' @param target String. Column name of the variable that supplies the values.
#' @param ... other parameters
#'
#' @return A ggplot object.
#' @export
#'
#' @examples
#' # Complete, reproducible example
#'
wjp_newfunction <- function(
    data,
    target,
    grouping,
    colors      = NULL,
    cvec        = NULL,
    labels      = NULL,
    ptheme      = WJP_theme(),
    show_legend = FALSE
) {

  # ===========================================================================
  # 1. RENAME VARIABLES
  # ===========================================================================
  # Use all_of() to rename columns safely
  data <- data %>%
    rename(
      target_var   = all_of(target),
      grouping_var = all_of(grouping)
    )

  # Handle optional parameters with NULL checks
  if (is.null(colors) || identical(colors, grouping)) {
    data <- data %>%
      mutate(colors_var = grouping_var)
  } else {
    data <- data %>%
      rename(colors_var = all_of(colors))
  }

  # ===========================================================================
  # 2. TRANSFORM DATA (if needed)
  # ===========================================================================
  # Calculations, ordering, etc.

  # ===========================================================================
  # 3. DEFAULT COLORS
  # ===========================================================================
  # Fall back to the WJP palette when no color vector is supplied
  if (is.null(cvec)) {
    cvec <- wjp_default_cvec(data$colors_var)
  }

  # ===========================================================================
  # 4. CREATE THE BASE CHART
  # ===========================================================================
  plt <- ggplot(data, aes(x = grouping_var, y = target_var, fill = colors_var)) +
    geom_col(show.legend = show_legend) +
    geom_text(
      aes(label = target_var),
      family   = wjp_font_family(),
      fontface = "bold",
      size     = 3.514598,
      color    = "#4a4a49"
    ) +
    scale_fill_manual(
      values = cvec,
      breaks = wjp_legend_breaks(data$colors_var),
      name   = NULL
    )

  # ===========================================================================
  # 5. APPLY THEME AND FINAL TWEAKS
  # ===========================================================================
  plt <- plt +
    ptheme +
    theme(
      # Chart-specific tweaks
    ) +
    wjp_legend_theme(show_legend)

  return(plt)
}
```

## Roxygen2 Documentation

### Required Tags

Every exported function MUST include:

``` r

#' @description
#' `r lifecycle::badge("experimental")`
#'
#' Description of the function.

#' @param name Type. Description of the parameter. Default is ...

#' @return Description of the returned value.

#' @export

#' @examples
#' # Complete, reproducible example
```

### Full Documentation Example

``` r

#' Plot a Bar Chart following WJP style guidelines
#'
#' @description
#' `r lifecycle::badge("experimental")`
#'
#' `wjp_bars()` takes a data frame with long-format data and returns a ggplot
#' object with a bar chart following WJP style guidelines.
#'
#' @param data Data frame containing the data to plot.
#' @param target String. Column name of the variable with values to plot.
#' @param grouping String. Column name of the grouping variable.
#' @param colors String. Column name for color grouping. Default is `NULL`.
#' @param cvec Named vector of hex colors. Default is `NULL` (the WJP palette,
#'   see [wjp_palette()], is applied).
#' @param ptheme ggplot theme to apply. Default is [WJP_theme()].
#'
#' @return A ggplot object.
#' @export
#'
#' @examples
#' # Always load the WJP fonts
#' wjp_fonts()
#'
#' # Prepare data
#' data4bars <- data.frame(
#'   country = c("A", "B", "C"),
#'   value   = c(45, 67, 23)
#' )
#'
#' # Create chart
#' wjp_bars(
#'   data4bars,
#'   target   = "value",
#'   grouping = "country"
#' )
```

### Deprecating a parameter

When a parameter is renamed or becomes unnecessary, keep it working and
signal the change with lifecycle:

``` r

#' @param old_name `r lifecycle::badge("deprecated")` Use `new_name` instead.
wjp_newfunction <- function(data, new_name = NULL, old_name = deprecated()) {
  if (lifecycle::is_present(old_name)) {
    lifecycle::deprecate_soft("1.2.0", "wjp_newfunction(old_name)", "wjp_newfunction(new_name)")
    if (is.null(new_name)) new_name <- old_name
  }
  ...
}
```

## Required Design Patterns

### 1. Data Format: Long/Tidy

All functions expect data in long (tidy) format:

``` r
# CORRECT - Long format
country    variable    value
"Mexico"   "Police"    45
"Mexico"   "Courts"    52
"Chile"    "Police"    67
"Chile"    "Courts"    71

# INCORRECT - Wide format
country    Police    Courts
"Mexico"   45        52
"Chile"    67        71
```

### 2. Color Vector (cvec)

The `cvec` parameter is a named vector:

``` r

cvec <- c(
  "Category A" = "#482d8b",
  "Category B" = "#2894aa",
  "Category C" = "#f26b21"
)
```

The names must match the values of the `colors` variable.

### 3. Handling NULL Parameters

Always provide sensible defaults:

``` r

# If colors is NULL, use grouping as the color variable
if (is.null(colors)) {
  data <- data %>%
    mutate(colors_var = grouping_var)
}

# If cvec is NULL, fall back to the WJP palette
if (is.null(cvec)) {
  cvec <- wjp_default_cvec(data$colors_var)
}
```

### 4. Typography

Use ONLY the fonts registered by
[`wjp_fonts()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_fonts.md)
and read the active family with
[`wjp_font_family()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_font_family.md),
so `options(wjpr.family = "Inter Tight")` switches every chart:

- `"Lato Full"` - Default for all chart text
- `"Lato Light"`, `"Lato Black"` - Lighter and heavier Lato weights
- `"Inter Tight"` - Alternative family

``` r

geom_text(
  family   = wjp_font_family(),
  fontface = "bold",
  size     = 3.514598   # 10 pt
)
```

### 5. Institutional Colors

Standard WJP colors for reference (full ordered palette:
[`wjp_palette()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_palette.md)):

``` r

# Primary
"#482d8b"  # WJP violet
"#2894aa"  # WJP teal-blue
"#f26b21"  # WJP orange

# Grays
"#555659"  # Text and supporting elements
"#524F4C"  # Axis text
"#4a4a49"  # Value labels
"#d1cfd1"  # Grid lines

# Text on dark backgrounds
"#ffffff"  # White
```

### 6. Avoid Duplicate Renames

When several parameters can point to the same column:

``` r

# If grouping == colors, do not rename twice
if (identical(grouping, colors)) {
  data <- data %>%
    mutate(colors_var = grouping_var)
} else {
  data <- data %>%
    rename(colors_var = all_of(colors))
}
```

## Contribution Checklist

Before submitting a PR, check:

### Code

Function follows the standard structure

Parameters use the standard names (`target`, `grouping`, `colors`, etc.)

NULL parameters handled correctly

No duplicate renames when parameters match

Uses `all_of()` for column selection

Falls back to the WJP palette when `cvec` is NULL

Text layers use
[`wjp_font_family()`](https://worldjusticeproject.github.io/WJPr/reference/wjp_font_family.md)

Theme applied through the `ptheme` parameter

Returns a ggplot object

### Documentation

Complete Roxygen2 documentation with all required tags

`@export` tag present

[`lifecycle::badge()`](https://lifecycle.r-lib.org/reference/badge.html)
in the description

Reproducible, working example

Parameters documented with type and description

Entry added to `NEWS.md`

### Testing

Tests added in `tests/testthat/` (returns a ggplot,
[`ggplot2::ggplot_build()`](https://ggplot2.tidyverse.org/reference/ggplot_build.html)
works, clear errors)

Documentation example runs without errors

`devtools::document()` updates NAMESPACE and `man/`

`devtools::check()` passes with 0 errors, 0 warnings, 0 notes

### Files

File named `{type}Chart.R`

Example image added to `man/figures/`

`data-raw/generate-examples.R` and `vignettes/articles/gallery.Rmd`
updated

Function registered in `_pkgdown.yml` (navbar menu and reference index)

`CLAUDE.md` updated with the new function

## Pull Request Process

### 1. Prepare the Environment

``` r

# Install development dependencies
install.packages(c("devtools", "roxygen2", "testthat", "pkgdown"))

# Clone the repository
# git clone https://github.com/worldjusticeproject/WJPr.git
```

### 2. Create a Branch

``` bash
git checkout -b feature/new-function
```

### 3. Develop

1.  Create the file `R/newfunctionChart.R`
2.  Write the function following the standard structure
3.  Document it with Roxygen2
4.  Add tests and an example to `data-raw/generate-examples.R`

### 4. Verify

``` r

# Regenerate documentation
devtools::document()

# Run the tests
devtools::test()

# Check the package
devtools::check()

# Try it locally
devtools::load_all()
# Run the function example
```

### 5. Generate the Example Image

``` r

source("data-raw/generate-examples.R")
```

### 6. Commit and Push

``` bash
git add .
git commit -m "Add wjp_newfunction() chart type"
git push origin feature/new-function
```

### 7. Open the Pull Request

- Descriptive title
- Description of the changes
- Screenshot of the generated chart
- Completed checklist (see `.github/pull_request_template.md`)

## FAQ

### How do I handle haven_labelled data?

Convert to native R types before processing:

``` r

data <- data %>%
  mutate(across(where(haven::is.labelled), ~ as.numeric(.x)))

# or, for a single column
data$q1a <- as.double(unclass(data$q1a))
```

### Can I add new dependencies?

Ask first: we prefer to keep dependencies to a minimum. If one is
needed:

1.  Add it to `Imports` in DESCRIPTION (or `Suggests` if it is optional)
2.  Call it as `package::function()`; for optional packages, guard the
    call with
    [`requireNamespace()`](https://rdrr.io/r/base/ns-load.html)
3.  Document why it is needed

### How do I test without installing the package?

``` r

devtools::load_all()  # Loads the functions without installing
```
